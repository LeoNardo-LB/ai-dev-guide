# 需求工作流（Requirements）

> 需求从登记到验收的全生命周期纪律，与登记三分离（backlog 索引 / journal 批次日志 / spec 设计决策）的流转规则。
> 优先级定义与状态流转的**唯一归宿**在本文 §3 与 §4。

## Use when

- 收到新需求或新 bug 反馈，决定登记还是立即处理时
- 开启新工作批次（创建 journal 文件）时
- 需求达到规模、需要决定是否写 spec 时（§6）
- 声称某条需求「完成」、或完结迁移时（§5）

## 1. 登记三分离

| 层 | 角色 | 形态 |
|----|------|------|
| backlog.md | **未决工作索引**：只保留尚未完结的卡片（≤3 行摘要 + 链接） | 完结即迁移，永不膨胀 |
| docs/journal/ | **批次执行与证据日志**：每批次一文件，开工时创建，append-only | 证据与完结条目的归宿 |
| docs/specs/ | **设计决策**：非显然取舍或跨会话上下文时写；验收后移入 docs/archive/specs/ | active 只含进行中设计 |

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 登记一律先进 backlog（卡片 ≤3 行），不依赖会话记忆 | 需求随会话丢失、重复登记 |
| 2 | 开工即建 journal 批次文件（scripts/new-batch.sh）；取证/验证证据写入 journal，不塞进卡片 | 卡片膨胀、证据蒸发 |
| 3 | 只记录原始现象，不做主观归因（分析由实现任务承接） | 错误归因误导实现方向 |
| 4 | 一条目一事：不同需求拆不同条目 | 验收时一半完成一半未完成 |

## 2. 需求来源与收集

| 来源 | 处理 |
|------|------|
| 用户口头反馈 | 当场登记原始现象，不现场深挖 |
| 审计/审查报告 | 按报告登记并注明来源与路径 |
| 开发中顺带发现 | 只登记不跑题（卡片 + journal 链接） |
| 同来源同日期一批 | 归入同一批次，命名「日期 + 来源 + 批次名」；journal 一文件 |
| 用户对某卡的反馈 | **归卡**：追加注记进该卡（backlog.sh note），不另开新卡；仅当引出独立缺陷才立新卡并两卡互引 |
| 验收 SKIP / 降级待补 | 显式记 SKIP 的验收项登记 P2 卡并注来源（[acceptance.md](./acceptance.md) 第 7 节），复查闭环后正常迁移——防待补项悬空无人复查 | |

## 3. 优先级定义（唯一归宿）

<!-- CANON:priority -->

| 等级 | 含义 | 判定问题 | 通用示例 |
|------|------|----------|----------|
| P0 | 影响主流程体验或核心业务场景的 bug | 主流程会坏、用户被卡住？ | 崩溃、核心链路不可用 |
| P1 | 主要业务流程的功能需求 | 属于主流程闭环的一部分？ | 主功能点、搜索、导出 |
| P2 | 优化与小 bug：不影响主流程的改进 | 不做也不影响主流程？ | 动画微调、文案、边界小 bug |
| P3 | 观察项 / 低价值改进 | 不做也无所谓？ | 偶发自愈异常、低频小改进 |
| P4 | 外部前提阻塞：方向明确但前提在项目之外 | 前提在上游/服务器/用户手里？卡内必含「前提」行（前提是什么、为何现在做不了、满足后如何接管） | 等上游修复、等用户开通权限 |

优先级在登记时初判、澄清时复核；P0 优先处理，会话忙时也先登记防丢失。优先级调整一律经 backlog.sh prio（note 留痕、计数器不动），禁手工跨节剪切；P4 前提满足后经 prio 重判回归 P0-P3。

## 4. 状态流转（唯一归宿）

<!-- CANON:status-flow -->

「完成」的判定按**关闭权限**分类（验收协议唯一归宿：[acceptance.md](./acceptance.md) 第 1 节）：仪器可验项 = 三步验收全绿 + 受端效果证据，AI 取证确凿后**直接关闭**；人工项（仅四类例外）= 用户确认后才关闭。代码写好但未验证不等于完成。

| 状态 | checkbox | 含义与流转规则 |
|------|----------|----------------|
| 进行中 | [ ] | 已登记或正在开发。开发完成、自动化验证（构建/测试/静态检查）通过后 → 转待验证；未验直迁（[ ]→迁出）仅在带显式依据时允许（第 5 节规则 4 的 -r 路径） |
| 待验证 | [~] | 代码完成、自动化通过，等待关闭判定。后续 agent 看到 [~]：先查该卡分类——仪器可验项走 [acceptance.md](./acceptance.md) 三步验收后直接关闭迁移；人工项（仅四类例外）向用户给出验证清单请其执行，通过 → 关闭迁移，发现问题 → 改回 [ ] 进入修复 |
| 已完成 | [x] | 仅迁移瞬间存在的过渡态：关闭条件满足后**当场迁入 journal**（backlog.sh migrate），backlog 顶层 [x] 残留为零（check.sh 门禁 9 强制） |

流转铁律：代码写好不等于完成；仪器可验项不取证就声称完成 = 虚假声明；人工项未经用户确认的关闭属违规。

## 5. 完结迁移（backlog → journal）

```
关闭条件满足（仪器可验 = 三步验收全绿 + 受端效果证据；人工项 = 用户确认）
  → 卡片勾 [x]（瞬间过渡态）
  → 原文（卡片全文 + 证据链接）迁入对应 journal 批次文件（不压缩不删改）
  → backlog 删除该卡片；「下一编号」计数器不动（编号永不回收）
  → 若有 spec：spec 移入 docs/archive/specs/，头部状态行更新，卡片引用路径同步
```

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 迁移与验收同一动作完成，不留「回头再迁」 | backlog 复膨胀 |
| 2 | 可复用的蒸馏结论提炼进 docs/research/；journal 只记执行与证据 | 蒸馏结论埋没在过程记录里 |
| 3 | 归档 spec 定期清理零外部引用者（git 历史永久可找回） | 归档目录混积死文档 |
| 4 | 未验证（[ ]）卡迁移须显式依据（backlog.sh migrate -r）；迁入节用标准标题「已完结卡片迁入（日期）」+ 迁入依据行 | 未验卡静默流失 |
| 5 | 迁移操作走 backlog.sh（自动建迁入节/删卡收敛/门禁自检），禁手工剪切 | 手滑丢卡或计数器错乱 |
| 6 | migrate 的迁入节写入是 journal append-only 的**唯一豁免写路径**（节末整块追加，历史行不动）；其余一律 journal append | 历史被改写，差异分析失真 |

### 裁决记录

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 用户裁决写入对应 journal 批次，前缀「用户裁决：」+ 原话/要点 + 日期 | 裁决蒸发，同一问题反复争辩 |
| 2 | 同域多次裁决以最新为准；新裁决落地时回写旧裁决域卡片注记 | 旧裁决复活执行 |
| 3 | 过程新问题默认登记 + 纳入本批修复；仅轻微问题累计超 10 个 / 改动面大（架构级）/ 硬阻碍（外部依赖）三者之一可只登记，批次末统一报告 | 批次无限膨胀或问题被静默丢弃 |

## 6. Spec 分流

满足任一规模触发条件 → 先写 spec（[spec.md](../templates/spec.md)）再实施：

| # | 触发条件 | 违反后果 |
|---|----------|----------|
| 1 | 跨文件、跨层改动 | 方案边界不清，反复返工 |
| 2 | 交互或状态流转复杂 | 状态分支漏设计 |
| 3 | 存在多个可选方案、需要取舍 | 决策无记录，方向反复横跳 |
| 4 | 触及承重规则（[architecture.md](../standards/architecture.md) §2） | 违反承重约束引入回归 |

简单小改（单文件、低风险、无取舍）直接做；spec 是权威，卡片只留摘要 + 链接。

## 7. 澄清与拆解

实现前按 [requirement.md](../templates/requirement.md) 将卡片展开为可执行规格：验收标准先行（可测试条件列表）→ 用户故事 → 非目标 → 子任务拆解 → 回填卡片链接。

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 验收标准先于实现写下（时间性现象先仪器取证，人工面仅四类例外——[verify.md](./verify.md) 第 8 节） | 实现完无法判定是否完成 |
| 2 | 澄清结果回填 backlog 卡片或链接的 spec，不散落会话 | 关键信息丢失 |
| 3 | 开始新任务前先扫 backlog 防重复 | 重复登记、重复实现 |

## 8. 周期审查

| 动作 | 内容 |
|------|------|
| 去重 | 合并重复卡片；删除失效卡片（周期审查唯一授权的手工删卡场景，须 journal append 留痕） |
| 催验收 | [~] 卡片向用户推送验证清单，推动闭环 |
| 查 P0 积压 | P0 是否被新任务覆盖 |
| 复查 P4 | 外部前提已满足的 P4 卡经 backlog.sh prio 重判优先级，接管实施 |
| 清 journal | 蒸馏结论入 research；纯过程记录评估归档 |
