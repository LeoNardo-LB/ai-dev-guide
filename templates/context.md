# 项目术语表模板（CONTEXT）

> 项目领域术语的唯一定义处：统一 agent 与人的用语，杜绝同一概念多名混用。
> init.sh 复制到项目根 CONTEXT.md；每个术语 = 定义 + Avoid 反例词。

## Use when

- 初始化项目术语表时
- 新概念命名、或发现近义词混用时（当场沉淀进表）
- 撰写文档/代码命名前查表对齐用语

## 模板本体

```markdown
# <项目名>

<一句话项目定位>——本文件是项目领域术语表（glossary），只定义概念，不记录实现。

## Language

**<术语>**:
<1-2 句定义：它是什么（不是它做什么）>
_Avoid_: <近义混用词>（<为何避免：与哪个概念混淆>）

**<术语>**:
<定义>
_Avoid_: <词>
```

## 适用范围与豁免（总则填空）

Avoid 约束只限**名称性使用**（文档叙述/commit/公告里的叫法）；以下豁免：

- 代码符号名/键名/枚举/包名（真相源是代码，不改代码只改文）
- 证据引用原样（日志/引文里的原词不改写）
- 历史产物（journal/归档 spec/CHANGELOG 历史段不豁免——新段必须用规范名）

## 收录判据

| 收 | 不收 |
|----|------|
| 项目特有的领域概念 | 通用工程概念（超时/重试/工厂模式） |
| 多人/多会话反复使用且需统一的核心词 | 只出现一次的临时词 |
| 有混淆史的近义词对（用 Avoid 钉死） | 代码符号名（真相源是代码） |

## agent 使用纪律

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 产出（文档/commit/回复）前先查本表；表不存在则静默继续，勿预建空表 | 小项目被过度工程 |
| 2 | 概念缺失是信号：能映射既有概念 → 用规范名重想；真缺口 → 登记新词条 | 生造平行词汇 |
| 3 | 输出与既有 ADR 冲突 → 显式提出分歧与依据，不静默绕开或覆盖 | 决策被无声改写 |

## 维护纪律

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 定义写「是什么」不写「做什么」；1-2 句收紧 | 表变成第二套文档 |
| 2 | 新术语命名冲突当场挑战：「你说的会话是 session 还是 conversation？」 | 用语分叉蔓延 |
| 3 | 代码与用户表述矛盾时以表为准并更新表 | agent 学到错误用语 |
