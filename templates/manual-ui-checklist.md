# 人工验证清单模板（Manual UI Checklist）

> UI 时间性现象的人工验证清单骨架：每条 = 操作路径 + 预期现象 + 判定标准。

## Use when

- 变更涉及动画、过渡、闪烁、计时、布局跳动、滚动、蒙版等时间性现象时
- 发版前 UI 人工走查时

## 清单格式

```markdown
| # | 操作路径 | 预期现象 | 判定标准 |
|---|---------|---------|---------|
| 1 | <可复现的点击/输入/滚动序列> | <现象过程本身（过渡如何发生、计时如何累加）> | <可判通过/失败的标准> |
```

| # | 列 | 填写要求 |
|---|-----|----------|
| 1 | 操作路径 | 具体到用户照做即可复现 |
| 2 | 预期现象 | 描述过程（不是最终状态） |
| 3 | 判定标准 | 可明确判定（全程无跳变/揭盖无闪烁）；禁止「看起来正常」 |
| 4 | 通用 | 一条验证项只对应一个时间性现象 |

## 触发判定（先仪器后人工）

出现时间性现象（闪烁 Flicker · 过渡 Transition · 计时重置 Timer Reset · 布局跳动 Layout Jump · 滚动抖动 Scroll Jitter · 蒙版揭盖 Mask Reveal）→ **先仪器取证**（录屏逐帧 + 像素采样，[evidence.md](../workflows/evidence.md) §5）；仅以下四类进本清单请用户验证（[verify.md](../workflows/verify.md) §8）：

① 真手指连续手势/体感 · ② 需用户凭据/跨设备 · ③ 数日级观察 · ④ 主观观感拍板（四类枚举唯一归宿：[verify.md](../workflows/verify.md) 第 8 节）——每项须标注类别与「为何仪器不可行」。

## 清单治理

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 按域边界汇总一份清单一次性提交（多卡同域合并），不逐卡打断用户 | 用户被反复打断，清单被搁置 |
| 2 | 清单是活文档：任何仪器验证覆盖的项（含他卡顺带验证）当场勾销；素材失效换素材或删项 | 已验项重复打扰，清单腐化 |

## 发版前冒烟走查路径

| # | 走查路径 | 检查重点 |
|---|----------|----------|
| 1 | 应用启动 → 首屏加载 | 启动过渡自然、加载指示无闪烁 |
| 2 | 列表加载（加载中/空/有数据） | 布局不跳动、骨架屏过渡平滑 |
| 3 | 流式内容更新（实时计时/计数/进度） | 计时连续累加不重置、更新无跳动 |
| 4 | 蒙版/遮罩流程（进入、揭开、退出） | 揭盖一次完成、无提前露底 |
| 5 | 长列表滚动 + 内容追加 | 视口稳定、无滚动抖动 |
| 6 | 错误 → 重试 → 恢复 | 错误提示可见、恢复可感知 |

走查按能力组织：变更涉及哪个能力就遍历哪条路径；发布前执行一次全量并记录结果。
