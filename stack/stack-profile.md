# 栈档案（Stack Profile）

> 本项目的语言与框架事实档案——全系统**唯一**的栈相关真相源。
> 其他文档只引用本文件，不重复版本号与命令。初始化新项目时按本模板填充。

## Use when

- 不确定构建命令、依赖版本、目录约定、平台约束时
- 新会话开始时快速对齐栈事实
- 评估技术栈更换时

## 填写规则

| # | 规则 |
|---|------|
| 1 | 单一真相源：依赖/编译版本以构建文件为准，本档案只记「哪个文件是真相源」，不复制版本号 |
| 2 | 每节给出精确可执行命令（含 flags 与超时）；命令符号 BUILD/TEST/RUN 在 §5 定义，全系统引用此处 |
| 3 | 目录约定写「事实」：哪个目录放什么、依赖方向 |
| 4 | 红线（版本/代理/签名）标注 ⚠，它们属于 AGENTS.md 内联候选 |

## 5. 构建与打包（命令符号定义处）

```
BUILD   # 编译检查命令（快速反馈），超时 N 秒——待填
TEST    # 单元测试命令（强制重跑防跳过），超时 N 秒——待填
RUN     # 完整构建命令，超时 N 秒——待填
```

三个符号是全系统文档引用命令的唯一词根：workflows 文档写「执行 BUILD」；具体命令、flags、超时只在此处定义（复制即缓存，缓存必过期）。

## 8. 平台硬约束（语言无关，换栈仍在）

这些约束不随语言/框架替换而消失——换栈后仍需逐条确认新栈如何满足：

| 约束 | 一句话规则 | 典型翻车点 |
|------|-----------|-----------|
| 主线程 UI 更新 | UI 状态变更只能在主线程执行 | 后台线程更新 UI → 崩溃 |
| 生命周期感知 | 长驻组件须感知生命周期，随生命周期取消/释放 | 无感知持续订阅 → 泄漏 |
| 进程死亡与状态恢复 | 进程被杀后用户可见状态必须可恢复 | 瞬时状态当持久状态 |
| 权限模型 | 敏感权限运行时动态申请，不静默假设已授权 | 声明后直接调用 → 异常 |
| 后台执行限制 | 长任务用前台机制承载 | 后台任务被系统杀死 |
| 混淆保留规则 | 保留规则随引入的库一并声明（序列化/反射类） | 只混淆不保留 → 运行时崩溃 |

## 9. 框架替换指南

本档案的核心价值：换技术栈时，这是一份可执行的替换清单。

| # | 步骤 |
|---|------|
| 1 | 逐节重填本档案 §1-§7：替换选型、命令与真相源 |
| 2 | 更新项目根 AGENTS.md：「构建命令」与「架构概览」两段，删除旧栈命令 |
| 3 | 审查绑定旧框架的示例文档（本档案 + 范例 + UI 约定 + 代码风格的语言绑定示例） |
| 4 | 试点编译验证：最小功能跑通 BUILD + TEST + RUN 再铺开 |
| 5 | 登记替换记录（何时/为何/从什么换到什么，[adr.md](../templates/adr.md)） |

选型判据（换之前逐项评估）：生态成熟度、AI 训练语料丰富度（选主流框架——小众框架下 agent 代码质量骤降）、社区活跃度、迁移成本。
