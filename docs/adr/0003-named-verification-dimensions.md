# 3. 验证维度命名化

| 字段 | 值 |
|------|----|
| 状态 | 已接受 |
| 日期 | 2026-08-21 |
| 决策者 | 用户 + agent |

## 上下文

v1.1 同一组验证维度有两套编号词汇，靠 2 张映射表和 4 处口径声明防漂移——映射表本身是词汇分叉的症状。

## 决策

五维改用名称：构建 build / 测试 test / 运行时 runtime / 遥测 telemetry / 人工 human。全系统唯一词汇；旧编号列入门禁 8 禁用词；验证文档从五份团簇（互指 16 边）重组为按 agent 问题切分的三份线性链。

## 备选方案

| 方案 | 理由 | 否决原因 |
|------|------|----------|
| 命名化（选定） | 消灭影子词汇 | — |
| 保留一套数字编号 | 顺序感 | 编号仍可分叉（v1.1 实证） |
| 字母编号 | 同上 | 同上 |

## 后果

正面：无映射表；文档按问题切分后每次加载恰好一份。
负面：失去数字隐含顺序；维度名称在 verify.md §2 表内自定义。
