# 2. 双平面部署（元层不随行）

| 字段 | 值 |
|------|----|
| 状态 | 已接受 |
| 日期 | 2026-08-21 |
| 决策者 | 用户 + agent |

## 上下文

v1.1 把文档系统自身的治理知识以 SHOULD/MUST 级别复制进每个目标项目，但目标项目的日常 agent 几乎没有触发这些文档的场景——元层随行是纯认知负载。

## 决策

文档分两个平面：deployed（复制进项目：内容+模板+登记骨架+编辑卡）与 source（仅源仓：治理三份+脚本+manifest+specs）。目标项目改文档的纪律由不到 30 行的编辑卡承载并指回源仓。

## 备选方案

| 方案 | 理由 | 否决原因 |
|------|------|----------|
| 双平面（选定） | 受众分离，索引净减 | — |
| 元层随行但降级 MAY | 折中 | 仍是复制面与漂移面 |
| 治理文档放网站 | 零随行 | 引入站点基建，违背零依赖可复制 |

## 后果

正面：部署面瘦身；治理规则演进不要求已部署项目同步。
负面：目标项目深度改文档时需回源仓取完整规范（编辑卡五律覆盖多数场景）。
