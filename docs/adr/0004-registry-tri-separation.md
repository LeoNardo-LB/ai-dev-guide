# 4. 登记三分离（backlog/journal/spec）

| 字段 | 值 |
|------|----|
| 状态 | 已接受 |
| 日期 | 2026-08-21 |
| 决策者 | 用户 + agent |

## 上下文

单一 backlog 承载未决索引、执行证据、完结历史三种负载：卡片越写越长、完结条目永久累积、设计决策无处安放——登记簿越厚扫描越被跳过（生产实证）。

## 决策

三层分离：backlog = 未决索引（卡片 ≤3 行 + 链接；完结即迁移，门禁 9 强制零残留 + 编号计数器）；journal = 批次执行与证据日志（开工时创建、append-only、完结条目原文迁入）；spec = 设计决策（非显然取舍才写；验收后移归档区）。配套 CONTEXT.md 术语表统一用语。

## 备选方案

| 方案 | 理由 | 否决原因 |
|------|------|----------|
| 三分离（选定） | 各层负载单一、backlog 恒薄 | — |
| 单一 backlog 加内链 | 改动小 | 三种负载仍互相挤压 |
| issue tracker 外置 | 工具成熟 | 违背零依赖、离线可用 |

## 后果

正面：backlog 永久不超 250 行；证据 append-only 可回溯；spec active 区只含进行中设计。
负面：完结多一次迁移动作（脚本 + 门禁降低成本）；三层目录需 init 时建立。
