# 写作规范（Writing for Agents）

> 面向 Agent 读者的写作规范：指针怎么写、信息放哪层、命题保全、按位置覆盖、推理泄漏分类与反模式。
> 修改本系统任何文档前必读（source 平面 MUST）。

## Use when

- 新增/修改任何文档、AGENTS.md 规则、manifest 条目前
- 评审文档、删改散文段落前（先过命题保全）

## 1. 指针写作（Context Pointer）

索引表里的一行就是一个**指针**：它同时做两件事——说明材料是什么 + 列出触发它的**分支**（Use when 列）。

| 规则 | 反例 |
|------|------|
| 前置触发词：指针第一个词就是触发它的词（发版前/声称完成前/编辑 X 前） | 「了解发版时请看…」 |
| 一分支一触发：每个独立分支只写一次；同义改写是重复 | 「发版时」「发布版本时」并列 |
| 砍身份冗余：正文已自带的身份信息不写进指针 | 「详细介绍了架构的架构文档」 |
| 三要素齐全：级别 + 用途 + Use when | 只写「看 docs/xxx.md」 |

判定：必须读的材料配弱指针 = 方差 bug——先锐化措辞，锐化无效才内联。

## 2. 信息分层

| 阶梯 | 位置 | 适用 |
|------|------|------|
| 1 文件内步骤 | 文档主流程 | 每个分支都要用的内容 |
| 2 文件内参考 | 同文档后半部 | 同行平级规则集 |
| 3 披露式参考 | 独立文件 + 指针 | 只有部分分支需要的内容 |

判据（分支测试）：每个分支都需要 → 内联；只有部分分支需要 → 外链。

共置：一个概念的「定义 + 规则 + 例外」放同一标题下（拆散 = 碎片化，复制 = 重复，两者都是病）。

## 3. 命题保全（删改前的安全网）

删改任何散文段落前，先枚举该段的全部事实子句；每个子句都必须在改写后存活，否则不许删：

| 子句类型 | 例 |
|----------|----|
| 行为者与动作 | 「构建在 CI 完成」 |
| 条件/时序/顺序 | 「版本号更新在构建之前」 |
| 情态 | 必须/可以/禁止 |
| 否定保证与例外 | 「不删除历史 Release」 |
| 所有权/副作用/失败后果 | 「回退 debug 签名 → 签名冲突」 |

只有修辞、重复、叙事可删。字数变少本身不是改进；砍掉任何事实子句的「精简」是破坏。

## 4. 按位置覆盖（该写的必须写）

这不是单向缩短流程：当代码、类型、结构无法传达必要契约时，必须补写。详见 [code-style.md](../standards/code-style.md) §4 注释覆盖矩阵（公开 API/铁律处/补丁处/内部/模块头/测试六位置各自的必写与禁写）。

## 5. 写作十律

| # | 律 | 违反后果 |
|---|----|----------|
| 1 | 一行一义：一条规则一个条目，不用段落混装多条 | 规则互相稀释 |
| 2 | 正向表述：写「要做什么」；禁令仅在无法正向表达时用 | 禁令激活被禁行为 |
| 3 | 每条规则附「违反后果」 | 规则成噪音 |
| 4 | 示例优于解释：代码/条目示例优先于三段式散文 | 理解偏移 |
| 5 | 命令符号化：BUILD/TEST/RUN 只在 stack-profile §5 定义，他处只引用符号 | 复制即缓存，缓存必过期 |
| 6 | 单一真相源 + CANON 标记：重复出现的表打上唯一归宿标记 | 改一处漏一处 |
| 7 | 不缓存环境：文件树/构建文件能查到的，不写进文档 | 必然过期 |
| 8 | 砍无效句：删掉后 agent 行为会变的句子才保留 | 白付加载税 |
| 9 | 行数预算：默认 250，例外经 manifest 申报 | 注意力稀释 |
| 10 | 陈旧即删：过期内容删除优先于标注 | 学会忽略整份文件 |

## 6. 推理泄漏分类（禁止写作视角残留）

泄漏 = 站在「作者会话」而非「仓库当前状态」视角写的散文。一个测试：**读者只看仓库（无会话记录/评审线程/未提交草稿）能否解析每个引用、验证每个断言**？不能 → 改写或删除。

| # | 泄漏类型 | 修法 |
|---|----------|------|
| 1 | 死引用（未提交草案的章节号、评审轮次编号） | 引用提交后的归宿，或改写为自足陈述 |
| 2 | 变更叙事（used-to/no-longer/「本次重构」） | 改写为现在时陈述；历史入 journal/CHANGELOG |
| 3 | 评审编排（「评审人确认」「被否决于评审」） | 保留决策与理由，删掉谁在何时说的 |
| 4 | 来源叙事（「由 X 项目融合而来」） | 删除；读者无法解析外部项目 |
| 5 | 控制流复述（先做 A 再做 B 的步骤走查） | 删除；保留非显性契约 |
| 6 | 犹疑残留（「暂时这样应该够」） | 升级为明确边界或登记 TODO |

合法归宿：journal、归档 spec、CHANGELOG、manifest replaces——变更故事住在登记层，不住规则层。

## 7. 反模式清单

| 反模式 | 正确做法 |
|--------|----------|
| 长段落散文讲规则 | 表格 + 一行一义 |
| 引用文档不给 Use when | 索引行三要素齐全 |
| 同一含义多处定义 | 单一真相源 + CANON 标记 |
| 抄构建文件里的版本号/命令 | 指向真相源或命令符号 |
| 用「重要!」强调每条规则 | 删非承重规则 |
| 魔法词无定义 | 术语表统一定义（[system-design.md](./system-design.md) §6） |
| 失效链接/过期命令残留 | 门禁 1/6 + 同 commit 更新 |
